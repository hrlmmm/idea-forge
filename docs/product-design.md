## 0. 设计靶心（一句话）

用户的研究资产散落在磁盘各处，**他最急的是「东西有人管、能看清」**。
因此本设计的每一处取舍都服务于三个动词：**归类（归属清晰）、收敛（40–50 个结果压进一张表）、浮现（agent 的结论主动到人眼前）**。
任何「看起来很酷但增加认知负担」的东西一律不做（v0.1 刻意克制）。

## 1. 关键设计决策摘要（先读这段，避免后面踩坑）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **强调色 = 靛蓝 Indigo `--accent-600: #3F4BD1`** | 中性灰打底时，靛蓝既有学术冷感又不刺眼；且**数据可视化分类色板被明确定义为「避开 230°–265° 蓝紫色相区间」**，因此强调色永远不会和图表里的某条序列撞色。热力图则反过来用**靛蓝单色渐变**，视觉上与强调色同源，读作「同一族信息」。 |
| D2 | **指标好坏方向默认不染色** | 平台领域无关，不知道 metric 越大越好还是越小越好。Δ 统一用中性灰 + `↑ ↓` 符号，**仅当用户在 metric 上显式声明 `higher_is_better` 后**才启用绿/红。这是防止"误读指标"的产品级护栏。 |
| D3 | **所有轴/列/筛选器从运行时实际键集合生成** | 硬编码任何字段名（lr / accuracy / influence_spread…）都违反领域无关原则。前端只允许消费「键名数组 + 类型推断结果」。 |
| D4 | **密度用一套令牌 + `[data-density]` 切换，不做两套样式** | 桌面 `compact`（表行 32px，一屏 30+ 行），移动 `comfortable`（行 44px、卡片化）。同一组件、同一套 class。 |
| D5 | **移动端 Idea 树降级为缩进列表，不做画布** | 手机上拖拽缩放图谱是灾难。画布仅在 ≥1024px 启用，<1024px 自动切缩进树。 |
| D6 | **进度条是不确定态（流动条纹），不显示百分比** | 平台不执行代码，拿不到 epoch 进度。除非 metrics 里存在用户指定为「进度源」的键，才切确定态。诚实优于假象。 |
| D7 | **agent 的一切写入都带来源徽章**（`自动` / `手动`） | 可追溯是被 agent 接管的前提。analysis 被人编辑后保留原版本，diff 可查。 |
| D8 | **不做浏览器系统通知** | v0.1 权限成本高、收益低。改用「页内 toast + 顶栏角标 + `document.title` 变化 + 移动端首页卡片插入」。 |

## 2. 信息架构与导航

### 2.1 五层领域如何在导航里串起来

```
Literature ──「+ 衍生 Idea」──▶ Idea（分支树）
                                  │
                                  ├─ 关联文献（回指 Literature，多对多，可解绑）
                                  ▼
                               Version（git_ref，a1 / a2 / a3…）
                                  │
                                  ▼
                               Experiment（params / metrics 键值）
                                  │
                                  ▼
                               Analysis（agent 或人写回，一等公民）
```

**串接方式（每一跳都要有一个可见的 UI 入口，不许只靠 URL）：**

| 起点 → 终点 | 入口 | 位置 |
|---|---|---|
| 文献 → Idea | 行内 hover 按钮「+ 衍生 Idea」 | 文献库每行右端 |
| Idea ↔ 文献 | 「关联文献」区块的「+ 添加」/ 解绑 ✕ | Idea 详情侧栏 |
| Idea → Version | Version 列表行（主区），点击进 Version | Idea 详情主区 |
| Version → Experiment | 实验表行 / 矩阵单元格 → 下钻抽屉 | Version 详情 |
| Experiment → Analysis | 右栏「Agent 分析」卡（默认展开） | 实验详情 |
| 任意 → 任意 | `Cmd/Ctrl + K` 全局搜索（跨文献/Idea/实验） | 顶栏 |

**面包屑**（贯穿所有详情页，桌面顶栏下方，高度 32px）：
`项目名 / Idea 名 / Version 名 / Experiment 短 ID`，每段可点击回跳，当前段用 `--neutral-800` 加粗，前段 `--neutral-500`。

### 2.2 侧边栏（桌面，固定 240px，可折叠至 56px 图标态）

```
┌────────────────────────────┐
│ ⬢ 项目：IM-复杂网络   ▾    │  ← 项目切换器（本地仓库根目录）
├────────────────────────────┤
│ ○ 今日动态        ⬤3       │  ← 角标=运行中+未读分析数
│ ○ 文献库                   │
│ ○ Idea 分支树              │  ← 桌面默认落地页
│ ○ 实验总览                 │  ← 跨 Idea 的全局实验表，按实验组分组
├────────────────────────────┤
│ IDEA 快捷跳转              │  ← 小标题，10px，--neutral-400
│  · 影响力最大化主干    v3   │
│    └ 贪心+度中心性    v2   │  ← 二级缩进 12px，最多展开两层
│    └ CELF 优化        v1   │
│  · 传播模型对比       v1   │
│  ─────────────────────     │
│  + 新建 Idea                │
├────────────────────────────┤
│ ▾ 索引状态 已同步 · 2 分钟前 │  ← 底部状态，点击手动重建索引
└────────────────────────────┘
```

- 选中项：`background: var(--accent-50)` + 左侧 3px `--accent-600` 竖条 + 文字 `--accent-700` 500 字重。
- 角标：`--fs-xs`，圆点/数字，`--danger-500` 底白字，`--r-full`。
- Idea 快捷跳转区在 Idea 数 > 12 时显示「查看全部」而非滚动（避免侧栏失控）。

### 2.3 顶栏（桌面，高 56px，白底 + `--border-subtle` 下边框）

`[面包屑/页面标题] ·············· [全局搜索 320px] [状态筛选] [活动指示] [二维码] [⋯]`

- **全局搜索**：`⌘K`，占位符「搜索文献 / Idea / 实验 / 参数值」，弹层分三组结果，键盘上下选择回车跳转。
- **状态筛选**（仅在实验相关页出现）：分段控件 4 段 —— `全部 / 运行中 / 完成 / 失败`，宽 208px 高 28px。
- **活动指示**：有 running 时显示脉冲蓝点 + 数量，点击展开下拉列出运行中实验（点击直达详情）。
- **二维码**：hover 弹出「在手机上打开」面板（局域网 URL + token + 二维码），用于手机访问同一 local core。

### 2.4 路由（hash 路由，单页应用，无需后端配合）

```
#/today                                                    今日动态（移动端默认）
#/literature                        ?tag=&derived=&q=&sort=  文献库
#/ideas                                                    Idea 分支树 / 列表
#/ideas/:ideaId                     ?tab=versions|analysis  Idea 详情
#/ideas/:ideaId/:versionId          ?view=table|matrix|diff|chart
#/ideas/:ideaId/:versionId/:expId                          实验详情
#/experiments                                              全局实验表（跨 Idea，按实验组分组）
```

- 视图切换（table / matrix / diff / chart）是 **同一路由下的 query 参数**，用分段控件切换，切换不丢筛选条件（筛选条件同步进 query，可分享/刷新保持）。
- 移动端用底部 tab bar 4 项：`今日 / 文献 / Idea / 实验`，高 56px + `env(safe-area-inset-bottom)`。

## 3. 全局设计令牌

> 落地方式：CSS 自定义属性，写在 `:root`。前端同事请**只允许**使用这些变量，禁止硬编码色值。

### 3.1 中性灰阶（打底，占界面 90%）

| Token | 值 | 用途 |
|---|---|---|
| `--neutral-0` | `#FFFFFF` | 卡片 / 表格 / 顶栏底 |
| `--neutral-25` | `#FCFCFD` | 页面底色（App 背景，卡片浮于其上） |
| `--neutral-50` | `#F7F8FA` | 表头 /  zebra 行 / hover 底 |
| `--neutral-100` | `#F1F2F5` | 分段控件容器 / 禁用底 / 输入框底 |
| `--neutral-150` | `#E9EBEF` | **默认描边 `--border-subtle`** |
| `--neutral-200` | `#E1E3E9` | **卡片描边 `--border`** |
| `--neutral-300` | `#CDD1DA` | 分割线 / 图表网格线 / 连接线 / 禁用文字 |
| `--neutral-400` | `#A8AEBB` | 占位符 / 次要图标 |
| `--neutral-500` | `#7E8698` | **次要文字（元信息、单位、时间戳）** |
| `--neutral-600` | `#5C6373` | 辅助正文 |
| `--neutral-700` | `#43485A` | **正文主色** |
| `--neutral-800` | `#2C3040` | **标题色** |
| `--neutral-900` | `#1A1D28` | 大数字 / 最强强调文字 |

### 3.2 强调色（Indigo，全站**唯一**强调色）

`--accent-50 #F1F3FE`（选中行底 / diff 高亮底）· `--accent-100 #E0E5FD`（焦点环 / 搜索命中高亮）· `--accent-200 #C3CBFB` · `--accent-300 #9DA9F7`（hover 连线）· `--accent-500 #5563EA` · **`--accent-600 #3F4BD1`（默认交互态：主按钮底、选中边框、链接、脉冲点）** · `--accent-700 #333CA8`（hover 态 / 强调文字）· `--accent-800 #2A3183`

**选择理由**：靛蓝色相 ≈ 245°，与学术/Notion 类产品的克制调性一致；更重要的是——**§3.4 的分类色板被硬性排除在 230°–265° 之外**，所以强调色与图表序列永不撞色；而对红绿色盲人群，靛蓝仍稳定可辨，比绿/红更适合做「交互态」的唯一载体。

### 3.3 状态色（success / warning / danger / info）

| 状态 | 50（底） | 500（主） | 600（文字/深） | 对应语义 |
|---|---|---|---|---|
| success | `#E8F6EE` | `#2F9E63` | `#217A4B` | done、已验证、通过 |
| warning | `#FEF4E6` | `#D98214` | `#A8630C` | 指标缺失、可疑结果、待确认 |
| danger | `#FDEDED` | `#D64545` | `#A93535` | failed、失败、破坏性操作 |
| info | `#EAF2FE` | `#3B82D6` | `#2C67AB` | 提示、说明、agent 自动来源 |

**使用纪律**：状态色只用于**表达状态**，绝不用于装饰或分组配色。同时出现多个状态色时，只有一个可以是「实心填充」，其余降级为「浅底 + 描边」。

### 3.4 数据可视化色板（与强调色不打架的关键）

- **分类色板（categorical，折线 series / 平行坐标分组，避开 230°–265°）**：
  `#D97757`（赭橙）· `#5B9E8A`（青绿）· `#C9A227`（芥黄）· `#7E9BC7`（灰蓝 210°）· `#B07AA1`（玫紫 320°）· `#8A8F98`（石墨灰）
  超出 6 组后循环并自动加 `--neutral-300` 虚线样式区分。
- **顺序色板（sequential，热力图 / 矩阵单元格，靛蓝单色 5 档）**：
  `#F1F3FE` → `#C3CBFB` → `#9DA9F7` → `#5563EA` → `#333CA8`
  数值型自动分位（quantile）而非等距，避免长尾数据全挤在一档。
- **缺失值**：`repeating-linear-gradient(45deg, var(--neutral-100) 0 4px, transparent 4px 8px)` 斜纹底 + 中心 `—`，**绝不填 0**（0 是有意义的数值，会误导）。
- **发散色板（diverging，Δ 相对 baseline，仅在用户声明 `higher_is_better` 后启用）**：`#217A4B → #F7F8FA → #A93535`。

### 3.5 字体

```css
--font-sans: "Inter", -apple-system, "SF Pro Text", "Segoe UI", Roboto,
             "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei",
             "Source Han Sans SC", "Noto Sans SC", sans-serif;
--font-mono: "JetBrains Mono", "SF Mono", "Cascadia Code", Consolas,
             "Courier New", monospace;   /* 参数值 / 指标值 / 路径 / 日志 / git hash */
```
- **西文在前、中文在后**，保证中英混排时英文用 Inter、中文回退苹方/雅黑，无需额外 font-family 切换。
- 所有数字（指标、ID、时间戳、表格数值列）加 `font-variant-numeric: tabular-nums`，保证列对齐。
- 参数键名用 `--font-mono` 13px，参数值用 `--font-mono` 13px —— **键值在视觉上必须像"代码"，和自然语言正文区分开**。

### 3.6 字号 / 行高

| Token | 桌面 | 移动 | 用途 |
|---|---|---|---|
| `--fs-xs` | 11px / 16 | 12px / 16 | 徽章、角标、图例、次要元信息 |
| `--fs-sm` | 12px / 18 | 13px / 18 | 表格内容、标签、面包屑 |
| `--fs-base` | 13px / 20 | 14px / 20 | 正文 |
| `--fs-md` | 15px / 22 | 16px / 24 | 卡片标题、区块标题 |
| `--fs-lg` | 18px / 26 | 18px / 26 | 页面标题 |
| `--fs-xl` | 22px / 30 | 22px / 30 | 大标题（概览数字区） |
| `--fs-metric` | 28px / 34 | 28px / 34 | 主指标大数字，600 字重，tabular-nums |

### 3.7 间距（4px 基准）、圆角、阴影、边框

- `--sp-1:4  --sp-2:8  --sp-3:12  --sp-4:16  --sp-5:20  --sp-6:24  --sp-8:32  --sp-10:40  --sp-12:48`
- 圆角：`--r-xs:3`（徽章）· `--r-sm:4`（chip / input）· `--r-md:6`（按钮 / 小卡）· `--r-lg:10`（卡片）· `--r-xl:14`（抽屉 / 弹层）· `--r-full:999`（徽章 / 圆点）
- 阴影（柔和、克制，符合"白底+柔和阴影"）：
  - `--shadow-xs: 0 1px 2px rgba(26,29,40,.05)`（表头吸顶）
  - `--shadow-sm: 0 1px 3px rgba(26,29,40,.06), 0 1px 2px rgba(26,29,40,.04)`（卡片静态）
  - `--shadow-md: 0 4px 12px rgba(26,29,40,.07), 0 1px 3px rgba(26,29,40,.05)`（卡片 hover / 下拉）
  - `--shadow-lg: 0 12px 32px rgba(26,29,40,.10), 0 2px 8px rgba(26,29,40,.06)`（抽屉 / 模态）
  - `--shadow-ring: 0 0 0 3px var(--accent-100)`（焦点环，**替代 outline**）
- 边框：`--border-subtle: var(--neutral-150)`（表格内线）· `--border: var(--neutral-200)`（卡片）· `--border-strong: var(--neutral-300)`（输入框 hover / 强调分隔）

### 3.8 密度令牌（`[data-density]` 切换，唯一密度机制）

```css
[data-density="compact"]      { --row-h:32px; --cell-px:8px;  --card-pad:12px;
                                --section-gap:16px; --fs-table:12px; --hit:28px; --chart-h:280px; }
[data-density="comfortable"]  { --row-h:44px; --cell-px:14px; --card-pad:16px;
                                --section-gap:20px; --fs-table:14px; --hit:44px; --chart-h:220px; }
```
**规则**：`<meta viewport>` 宽度 ≥1024px → `compact`；<1024px → `comfortable`。用户可在设置里强制覆盖（桌面用户若偏好宽松，一键切换）。
**移动端额外规则**：≤768px 时，**所有宽度 > 720px 的数据表格自动转置为卡片列表**（见 §6.3），矩阵视图转置为「行=版本、横向滚动」的简化版。

## 4. 四大核心视图

> 每个视图统一三区结构：**工具条（sticky，高 44px）→ 主内容区（滚动）→ 次要面板（右侧抽屉 / 侧栏，按需）**。

### 4.1 文献库 `#/literature`

**页面目标**：把 PDF+笔记+标签收拢，并**一眼看出哪些文献已经长成了 Idea、哪些还躺在角落**。

**布局分区**
```
┌ 工具条 ────────────────────────────────────────────────────────┐
│ [🔍 搜索(320px,⌘K)]  [标签: 复杂网络× 传播模型× +]   [全部|已衍生|未衍生] [排序▾] [列表|网格] │
├──────────────┬─────────────────────────────────────────────────┤
│ 标签云(180px) │  列表区（每行 44px，compact 下 40px）              │
│ 多选+计数     │  ……                                              │
└──────────────┴─────────────────────────────────────────────────┘
```

**列表行内容**（从左到右，单列宽用 fr）：
`📄 标题（--fs-md，--neutral-800，hover 变 --accent-700 且下划线）` ·
`作者 et al. · 2023 · NeurIPS（--fs-sm，--neutral-500）` ·
`标签 chips（最多 3 个 + "+2"）` ·
`派生徽章：Idea 2（n>0 → accent-50 底 + accent-700 字 + 边框 accent-200；n=0 → 灰描边 + neutral-500 字）` ·
`阅读状态圆点（已读实心 neutral-400 / 在读半环 accent-500 / 未读空心 neutral-300）` ·
`hover 才出现的行内操作：打开 PDF ▸ / + 衍生 Idea ▸ / ⋯（编辑标签、解绑、软删除）`

**关键交互**
- **搜索**：标题 + 作者 + 笔记全文匹配，debounce 200ms；命中片段在结果里用 `--accent-100` 背景高亮。输入框右侧有 ✕ 清空。
- **标签筛选器**：在工具条第二排的 chip 行，横向可滚动，chip 高 24px（`--r-sm`），未选 = 白底 + `--border`，**选中 = `--accent-50` 底 + `--accent-700` 字 + `--accent-200` 边框 + 前置 ✓**。多选为 OR；左侧标签云与它双向同步。
- **「是否已衍生 Idea」筛选**：**分段控件（SegmentedControl）**，位置在工具条右侧、排序下拉左边，容器 `--neutral-100` + `--r-md` + 内 padding 2px，每段宽 72px 高 26px，选中段白底 + `--shadow-xs` + `--neutral-800` 字。三段：`全部 / 已衍生 / 未衍生`。
- **排序**：下拉（最近添加 / 标题 A-Z / 年份倒序 / 派生 Idea 数）。
- **「+ 衍生 Idea」**（核心动作）：点击 → **右侧滑出抽屉 420px**（`--shadow-lg`）：
  ① Idea 名称输入（自动预填文献标题，可改）
  ② 父节点选择器（树形下拉，默认「未分类 Idea」根）
  ③ 关联文献（当前这篇已预置为 chip，可继续添加 / ✕ 移除）

## 5. 参数变体可视化（本产品的灵魂功能）

> 前提：平台**不认识任何字段名**。所有聚类、diff、图表轴都基于**运行时从当前 Version 下实验集合算出的键集合**。

### 5.1 变体族（Variant Family）自动聚类 —— 给前端的**确定性算法**

在**单个 Version 范围**内执行（前端本地即可算，数据量 < 100）：

1. 取该 Version 下所有实验的 `params` 键并集 `K`。
2. 标记 **repeat 键**：键名匹配 `/^(.*_)?(seed|random_seed|repeat|run_id|trial|idx)$/i` 的键，**不参与差异判断**（它们只是重复实验的扰动，不是变量）。
3. 对每个非 repeat 键 `k`，计算取值基数 `|V(k)|`（值先做字符串归一化后去重）：
   - `|V(k)| == 1` → **常量键**（constant）
   - `|V(k)| >= 2` → **差异维度**（difference dimension），记入 `D`
4. 用 `D` 上的取值组合对实验分组：组合相同 → 同一**配置组**（同组内的实验互为 repeat）。
5. 聚类判定：
   - `|D| == 0` → 单一配置组，标题显示为「重复实验 ×N」，不叫族。
   - `1 <= |D| <= 3` 且实验数 ≥ 2 → **变体族（Variant Family）**，命名 `a2 · 变体族 #1`，副标题 chip 列出 `D` 中的键。
   - `|D| > 3` → 不强行成族，标记为「**广域搜索**」（`--warning-500` chip 提示「差异维度 5 个，建议用平行坐标查看」），此时按实验创建时间顺序平铺。
6. **允许人工干预**：族卡右上角「调整维度」→ 弹出维度复选面板（列出 `K` 全部键 + 各自基数 + 是否 repeat），用户勾选/取消后**前端本地重算分组**（不写库，仅存为视图预设），并提示「已按手动维度重算」。

**UI 摆放**：Version 详情页的 `对比` 视图顶部，以可折叠的族卡片列表呈现；每族卡显示：族名 + 差异维度 chips + 实验数 + 最佳指标 + 「展开成员」+ 「族内对比」按钮。

### 5.2 两个实验并排 Param Diff

**入口**（三处）：
① Version 实验表中勾选 **2 个**实验 → 顶部浮出操作条「对比选中的 2 个」（勾选 >2 时提示「对比一次支持 2 个，已选 4 个，将只取前 2 个」+ 提供「清空选择」）；
② 实验详情的 params 面板「与…对比」下拉；
③ 族卡「族内对比」默认选中该族 baseline 与最佳实验。

**布局**：三栏表 `[键 32%] [A 28%] [B 28%] [Δ 12%]`，行高 `--row-h`，顶部 sticky 的 A/B 选择下拉 + `⇄ 交换` 按钮 + `[复制为 Markdown]` + `[设为 baseline]` + `[仅看差异]` 开关。

**行规则（视觉纪律，务必逐条实现）**

| 情况 | 呈现 |
|---|---|
| **同键同值** | **默认折叠**进底部「相同参数（n 项）」折叠区（点击展开）；展开后文本 `--neutral-400`，无背景色，左侧 3px 透明占位（保持列对齐） |
| **同键异值** | 行底 `--accent-50`，左侧 3px `--accent-600` 竖条，A 值 `--neutral-500` 加删除线效果（用 `text-decoration: line-through` + `--neutral-400`），B 值 `--accent-700` 600 字重，中间用 `→` 连接 |
| **仅 A 有 / 仅 B 有** | 行底 `--warning-50`，左侧 3px `--warning-500` 竖条，缺失侧显示 `—`（`--neutral-300`），并加 `仅左侧` / `仅右侧` 小徽章 |
| **数值型键** | Δ 列显示 `+0.0004 (+12.3%)`：差异值 + 括号百分比（baseline 为 0 时只显示绝对值） |
| **非数值型键**（字符串/布尔） | Δ 列显示 `≠` 符号，不计算差值 |

**Δ 的染色规则（落实 D2）**：
- **默认**：Δ 文字 `--neutral-600`，前缀符号 `↑` / `↓` / `±`（变化 < 0.1% 显示 `±`）——**不染绿红**，因为平台不知道方向好坏。
- **仅当**该 metric 被用户声明 `higher_is_better: true/false`，或该键为 **param**（参数无好坏）时……精确规则：
  - params 的 Δ **永不染色**（参数没有好坏）。
  - metrics 的 Δ：未声明方向 → `--neutral-600` + `↑↓`；已声明 → 变好 `--success-600`、变差 `--danger-600`。
  - Δ 旁有一个 `⋯` 小按钮可就地声明方向，声明后立即重染。

**Metrics 段**：同样的三栏表，位于 params 表下方，用 `--border-strong` 分隔并加小标题「指标」。缺失 metric 显示 `—`（`--neutral-300`），**不参与 Δ 计算**。

**顶部摘要条**（紧贴工具条下方，`--neutral-50` 底，`--r-md`，padding `--sp-3`）：
`本次差异：3 个参数（lr · dropout · hidden_dim） · 1 个指标变化（influence_spread ↑ 0.032） · 其余 17 项相同`
右侧按钮 `[复制为 Markdown]`（生成可直接粘进论文/汇报的表格文本）。

### 5.3 图表区（所有轴动态生成）

**位置**：Version 详情页 `图表` 视图（`#/…/:versionId?view=chart`）。顶部**分段控件**切换四种：`折线 / 热力图 / 平行坐标 / 表格`。高度 `--chart-h`（桌面 280px，移动 220px），白底卡片 + `--border` + `--shadow-sm`。

**轴选择器（AxisPicker，所有图表共用）**
- 位置：图表卡右上角，两个下拉 `X 轴 ▾` `Y 轴 ▾`（平行坐标是「维度多选」）。
- 选项来源：**当前 Version 下实验的 params ∪ metrics 键并集**，按 `params.*` / `metrics.*` 分组（optgroup）。
- 每个选项右侧显示类型图标 + 取值基数 `n=5`。
- **非数值型键置灰不可选**，hover tooltip 说明「该键取值非数值（字符串/布尔），不能作为坐标轴」。
- 数值型判定：该键在 ≥80% 出现次数中可 `parseFloat` 成功。

**① 单参数扫描折线（LineScan）**
- 触发条件：X 轴选中键的**数值型取值基数 ≥ 3**；否则图表区显示引导态「『xxx』只有 2 个取值，样本太少，折线意义不大 —— 试试用「对比」看差异，或换一个维度」。
- Y 轴 = 一个 metric 键。
- **歧义消解（重要）**：若除 X 外还有其他差异维度（`D \ {X}` 非空），图表上方强制出现「**固定维度**」chip 行：每个其他差异维度一个下拉，默认选第一个取值，chip 显示 `dropout = 0.3`。未固定的维度会在 tooltip 里提示「此点还受 dropout 影响」。
- 点：默认 5px 实心圆（分类色板）；**failed 实验画空心叉（`×`，`--danger-500`）**；running 画空心圈（`--accent-500`）。hover 显示完整 tooltip（实验名 + 全部 params 摘要 + metric 值 + 点击跳转）。
- 折线只连**同一固定维度组合**的点；不同组合用不同颜色 series（最多 6 条，图例在右下角，`--fs-xs`）。

**② 双参数热力图（HeatmapGrid）**
- X = param 键 A，Y = param 键 B（均要求基数 2–12，超出提示先筛选）。
- 单元格 = 该 (A,B) 组合下 metric 的聚合值（默认最大值，可切），用**顺序色板 5 档**填充；数值直接写在格内（`--fs-xs`，按背景深浅自动切黑/白字）。
- **无数据的组合：斜纹缺失底 + `—`，绝不填 0**。
- 单元格 click → 下钻该组合下的实验列表（抽屉）。
- 右侧色阶图例（垂直渐变条 + min/max），底部空态说明「缺失组合显示为斜纹」。

**③ 平行坐标（ParallelCoordinates）**
- 适用：`|D| >= 3` 的广域搜索场景（也是 5.1 里给的建议去向）。
- 纵轴 = 每个**数值型差异维度** + 选中的 1 个 metric（顺序：params 在前、metric 在最后，metric 轴加粗并加 `--accent-200` 底纹以突出）。
- 一条线 = 一个实验，线宽 1.5px，默认 `--neutral-300` + `opacity:.5`；**hover 高亮为 `--accent-600` 并置顶**（其他线降到 `opacity:.15`）；click 锁定选中并右侧显示该实验摘要卡。
- **刷选（brush）**：在任意轴上拖拽区间 → 过滤掉区间外的实验，**联动该 Version 下的实验表**（同一页面内的表格实时过滤），顶部显示「已过滤：保留 12 / 30」+ `清除刷选`。
- 轴标题下方显示该轴的 min/max（`--fs-xs --neutral-400`）。

**④ 表格**：就是实验表，保留在此作为「不想看图时」的兜底，且保证刷选状态同步。

## 6. 移动端视图（`≤768px`，`data-density="comfortable"`）

**设计原则：手机上是「扫一眼」，不是「干活」。** 首页只回答三个问题：**有没有在跑、今天出了什么、agent 说了什么。**

### 6.1 首页 `#/today`（移动端默认落地）

垂直单列流，从上到下**只有三块**，总高度控制在一屏半内扫完（超出部分可滚）：

**块 1 · 运行中（`进行中 (n)`）**
- 无运行中实验时：**整块隐藏**（不是显示空态 —— 手机上"没有消息"不需要占位）。
- 每张卡（`--r-lg`，白底，`--shadow-sm`，padding `--sp-4`）：
  - 第一行：所属面包屑 `影响力最大化主干 / a2`（`--fs-xs --neutral-500`，可点击）
  - 第二行：实验名（`--fs-md` 600）+ 右侧 StatusBadge（running，脉冲点）
  - 第三行：**不确定态进度条**（高 6px，`--r-full`，`--accent-200` 底 + 45° 流动条纹动画 1.4s linear infinite）—— 落实 D6，不显示百分比
  - 第四行：`已运行 2 小时 14 分 · 上次心跳 12 秒前`（`--fs-xs --neutral-400`）
- 超过 3 张 → 只显示前 3，底部「查看全部 5 个运行中」。

**块 2 · 今日结果（`今日完成 / 失败`）**
- 卡片按完成时间倒序，done 与 failed 混排（**failed 优先置顶**，因为更需要处理）。
- 卡片内容：面包屑 + 实验名 + **主指标大数字（右对齐，`--fs-metric`）** + 指标名（`--fs-xs mono`）+ **相对 baseline 的 Δ**（`↑ 0.032`，中性灰或已声明方向的绿红）。
- failed 卡：左侧 4px `--danger-500` 竖条 + 标题下追加一行错误摘要（`--fs-sm --danger-600`，日志里最后一个 `Error:` 行，单行截断）。
- 指标缺失的 done 卡：追加 `--warning-500` 的「指标缺失」chip（与桌面一致）。
- 今日无结果 → 显示一行弱化文字「今天还没有完成的实验」（保留，因为这是"今日"语义，用户会找）。

**块 3 · Agent 新分析（`Agent 新分析 (n)`，n = 未读数）**
- 每张卡：来源徽章 `🤖 Agent 自动` + agent 标识 + 时间 + 右上角**未读小圆点**（`--accent-600` 6px）
- 摘要：分析正文的**前 2 行**（`--fs-base --neutral-700`，`line-clamp: 2`），被引用的 metric 键渲染为 chip（同桌面）
- 底部：`展开全文 ▾`（展开后 Markdown 全渲染 + 「跳转到实验」）
- 卡右侧滑动手势：左滑 → `标记已读`（`--neutral-100` 底）；块标题右侧有「全部已读」文字按钮
- 无未读 → 显示弱化一行「暂无新的 agent 分析」

### 6.2 底部 Tab Bar
高 56px + 安全区，白底 + 顶部 `--border-subtle`，5 项等宽：`今日 / 文献 / Idea / 实验 / 执行记录`。
图标 20px（线性风格，1.5px 描边）+ 文字 `--fs-xs`；选中项图标与文字均 `--accent-600`，未选 `--neutral-400`。「执行记录」与「今日」显示数字角标（`--danger-500` 底白字）。

### 6.3 移动端通用降级规则
- **表格 → 卡片列表**：任何列数 > 4 的表，在 ≤768px 自动转为卡片（每张卡 = 原表一行，标题取第一列，其余以「键: 值」两列排版）。

## 7. Agent 闭环在 UI 上的体现

### 7.1 实验状态（`pending → running → done / failed`）在各视图的表达

统一使用 `StatusBadge` 组件，**四种状态 + 一种降级态**：

| 状态 | 徽章 | 点 | 底色 | 文字 | 动效 |
|---|---|---|---|---|---|
| `pending` | `待运行` | 空心圆（边框 `--neutral-400`） | `--neutral-50` | `--neutral-600` | 无 |
| `running` | `运行中` | 实心圆 `--accent-600` | `--accent-50` | `--accent-700` | **脉冲动画**（`box-shadow` 扩散 1.6s infinite）|
| `done` | `完成` | 实心圆 `--success-500` | `--success-50` | `--success-600` | 无 |
| `done` 且 metrics 缺失 | `完成·缺指标` | 三角 `--warning-500` | `--warning-50` | `--warning-600` | 无（**蓝图风险项：缺失标 warning 而非静默 done**）|
| `failed` | `失败` | 实心圆 `--danger-500` | `--danger-50` | `--danger-600` | 无 |

**在各视图的落点**：
- **实验表**：状态列（宽 88px，固定第一列右侧）用徽章；整行左侧 3px 状态竖条。
- **矩阵**：单元格右上角标数字 + 底部状态构成条（见 §4.3）。
- **Idea 树节点**：有 running 时节点角标位置显示脉冲点；有 failed 时显示 `--danger-500` 小点。
- **实验详情**：页头徽章（大号，高 24px）。
- **全局顶栏**：有 running → 活动指示脉冲点 + 数字，点击展开下拉列全部运行中实验。
- **移动端首页**：块 1（running 卡，带不确定态进度条）+ 块 2（done/failed 卡）。

### 7.2 长训练完成后，agent 的分析如何"浮现"到用户面前

触发链：`本地 python train.py 结束 → 写 done-sentinel → Watcher 感知 → local core 更新状态 + 写 analysis → 推 SSE 事件 → 前端`

前端收到事件后**同时**做四件事（不做系统通知，见 D8）：
1. **页内 toast**（右下角，`--shadow-lg`，5s 自动消失）：「`a2 · exp-047` 已完成，Agent 写了一份分析」+ 按钮 `[查看]`。多条合并为「3 个实验完成」。
2. **顶栏 / Tab Bar 角标** `+1`（执行记录与今日各一），未读清零前持续显示。
3. **`document.title`** 变为 `⬤ (3) Idea Forge`，页面重新聚焦后还原。
4. **移动端首页块 3 顶部插入新分析卡**（带 3s 的 `--accent-50` 高亮淡出，表示"新"）。

**"新"标记的生命周期**：实验卡上出现 `NEW` 徽章（`--accent-600` 底白字，`--fs-xs`），**24 小时后自动消失**（或用户点开后消失，取先到者）。

**SSE 断线处理**：连接断开时顶栏显示 `--warning-500` 的「实时连接已断开 · 点击重连」；重连成功后补一次全量拉取，避免漏事件。

### 7.3 「Agent 提议 → 人批准」在 UI 上长什么样

> ⚠️ **已废弃（2026-08-31）**：审批在**与 agent 的对话中**完成，网页无审批视图。本节仅留作历史参考。

**位置**：原 `#/agent-log` **Agent 执行记录**，页内两个 tab：`待批准提议 (n)` / `未读分析 (m)`。

**提议卡（ProposalCard）**，白底卡片，`--border` + 左侧 3px `--accent-600` 竖条，结构：

```
┌─ 待批准提议 ────────────────────────────────────────────────┐
│ 🤖 Agent 自动 · 08-31 14:22 · 基于 exp-041、exp-043          │  ← 来源徽章 + 时间 + 引用
│                                                              │
│ 建议：在 a2 上试 lr=0.005 + dropout=0.3                       │  ← 标题（--fs-md 600）
│                                                              │
│ 理由                                                         │
│ 在 a2 上 lr 从 0.001 提到 0.01 时 influence_spread 持续上升，  │  ← Markdown 正文
│ 但 0.01 出现震荡。建议插入 0.005 一档，同时加 dropout 0.3     │     引用的 metric 键
│ 抑制过拟合。参考 exp-041 的 influence_spread=0.462。          │      自动渲染为 chip
│                                                              │
│ 拟创建的实验参数                                              │
│ ┌────────────────────────────────────────────┐              │
│ │ lr          0.001  →  0.005     ↑          │              │  ← 相对 baseline 的
│ │ dropout     0.1    →  0.3       ↑          │                 mini diff（复用 §5.2
│ │ 其余 15 项与 exp-041 相同         展开 ▾      │                 的行规则，只读）
│ └────────────────────────────────────────────┘              │
│ 目标版本：a2 (#8b1d4f) · 预计运行 ~2 小时                     │
│                                                              │
│ [批准并创建]  [修改参数]  [拒绝]                              │
└──────────────────────────────────────────────────────────────┘
```

**三个动作的后果（必须明确）**：
- **批准并创建** → 以 `pending` 状态在目标 Version 下创建 Experiment（params 照抄提议），卡片变为「已批准」success 态并移入历史；toast「已在 a2 下创建 exp-048（待运行）」+ 提供「复制运行命令」。**平台不执行代码**（落实产品约束）。
- **修改参数** → 打开与「复制参数新建」相同的抽屉（差异键高亮），改完走「批准并创建」。
- **拒绝** → 弹出小输入框「（可选）告诉 agent 为什么拒绝」，内容回写给 agent（作为下次提议的约束）；不填也可直接拒绝。

**批处理**：列表顶部有全选勾选框，选中多条后浮出操作条 `[批准选中的 3 条] [拒绝选中的 3 条]`。
**排序**：按 agent 的置信度/时间倒序（v0.1 用时间倒序，置信度为可选字段，有则显示 chip `置信度 0.72`）。
**空态**：「没有待批准的提议 —— agent 会在需要你拍板时出现这里」+ 说明文字「提议不会自动执行，任何时候都由你决定」。

**权限边界的视觉声明**：执行记录页顶部有一条常驻说明条（`--neutral-50` 底，`--fs-sm --neutral-600`）：
「Agent 可以**创建实验记录、写入分析、提出提议**；**不会**执行代码、删除数据或修改已有实验结果。所有 agent 写入都带 🤖 来源徽章。」
—— 这直接回应"被 agent 接管"的信任问题，必须在 UI 上明说。

### 7.4 实验组（实验线）分组视图（2026-09-01 新增）

**动机**：一个 Idea 的验证分阶段、分目的推进——先用小数据做**可行性验证**，再上**正式对比**（完整实现 + 基线），再做**消融**。每组实验对应一个验证目的，天然构成"验证路线"。

**位置**：`#/experiments` 实验总览。分组层级为 **实验组 → 实验**（组头替代原先的 Version 分组头；Version 信息保留在实验行的 commit 列）。

**实验组卡片（GroupCard）**：
- 组头：组名 + 状态徽章（`planning 规划中` / `active 进行中` / `done 已完成` / `abandoned 已放弃`，色值复用 §3.3 状态色）+ 组 id（mono）+ 右侧实验计数。
- 目的行：`验证目的：…`（组创建时的 purpose 字段，`--neutral-500` 小字）。
- 结论行：若已填 conclusion，显示 `结论：…`（`--success-700`）。
- 组内：实验表（列同 §4.3：实验 / 名称 / 状态 / commit / 创建）。
- **未分组区**：`groupId` 为空的实验收进"未分组"卡，置于所有组之后。
- **空态**：无实验组时显示引导文案「让 agent 用 create_experiment_group 建组（如可行性验证 / 正式对比 / 消融），再把实验挂进组里」。

**数据契约**：实验组由 agent 经 MCP（`create_experiment_group` / `update_experiment_group` / `list_experiment_groups`）创建与维护；前端只读展示。实验通过 `groupId` 归组（`create_experiment` 可选传 `group_id`）。

### 8.3 组件复用的三条硬规则
1. `StatusBadge` 是全站表达实验状态的**唯一**组件 —— 任何页面不得自造状态样式。
2. `KeyValuePanel` 的 `diff` 模式与 `DiffTable` 的行规则**必须共用同一套视觉 token**（同值淡灰 / 异值 accent / 单侧 warning / Δ 中性优先），避免出现两处 diff 长得不一样。
3. 所有键名（`params` / `metrics` / git hash / 路径 / ID）一律 `--font-mono`；所有自然语言正文一律 `--font-sans`。这条规则不允许例外。

## 11. 修订（2026-08-31）：增加"研究方向"顶层 + Idea↔git 分支 + 文献跨方向共用 + 实验界面可定制

> 本节是对前面章节的**覆盖性修订**，冲突以本节为准。

### 11.1 新的顶层：研究方向（Direction）
在 Literature 之上新增一层 **Direction（研究方向）**。一个 Direction = 一个独立的研究项目 = **一个独立 GitHub 仓库 + 一个本地目录**。

新分层：
```
Direction（研究方向 = 一个仓库）→ Literature → Idea（= 该仓库的一条 git 分支）→ Version（= 该分支上的某次 commit）→ Experiment → Analysis
```

- **隔离**：不同 Direction 的文献库、Idea 树、实验**默认互不可见**。侧栏顶部的「研究方向切换器」切换当前 Direction；切换后文献库/Idea/实验总览均按此 Direction 过滤。
- **今日动态**是**跨方向**的（人扫一眼全局，不分方向）。
- 一个用户可有任意多个 Direction；每个 Direction 独立目录、独立 git 仓库、独立 `.research/` 元数据。

### 11.2 Idea ↔ git 分支
- 每个 Idea **对应本 Direction 仓库的一条 git branch**（如 `im/influence-max-main`、`robust/attack-perturbation`）。
- **Version 仍存在**，语义为「该分支上的某次 commit」——同一 Idea 演进的不同代码状态对应不同 Version。
- 新建 Idea = 在仓库里新建一条 branch；放弃 Idea = 软删除（保留 branch 记录，标记 `abandoned`，不删分支历史）。
- Idea 节点 UI 显示 `⎇ <branch-name>`；Version 仍显示 `#<short-hash>`。

### 11.3 文献：全局库 + 方向标签 + 跨方向共用
- 文献是**全局库**，但每篇带 `directions: []`（可多选，支持一篇文献同时属于多个方向 = 共用）。
- 文献库视图默认只显示**当前 Direction**的文献（含共用）；提供筛选 `本方向 / 含共用 / 仅独有`。
- 共用文献在列表里标 `共用` 徽章 + 所属方向 chips；可「从其它方向引用」把已有文献加入当前方向。
- 这解决"不同方向文献可能不同，但有些文献共用"的诉求。

### 11.4 实验界面可定制（强化 §4.3 / §4.4）
- **实验总览新增「表格」视图**（与矩阵/对比/图表并列分段）：
  - 默认列：实验 / 状态 / 时间。
  - **自定义列抽屉**：列出当前 Idea 下所有 params ∪ metrics 键（按 params/metrics 分组，显示出现次数），用户勾选任意键作为列；列集合存为**视图预设**（可命名、可复用）。
  - 列来自运行时键集合——换一个 Idea/Direction，列自动跟着变（不写死）。
- 矩阵视图的「指标」下拉、Param Diff 的 A/B 选择、图表的 X/Y 轴，全部沿用 §3「从键集合动态生成」原则，不做任何字段硬编码。
- Agent 可通过 MCP 自定义实验的 metrics schema（声明键名+类型+方向），平台不预设任何指标。

### 11.5 对前面章节的覆盖点
- §2 导航：侧栏顶部「项目切换器」占位**激活为 Direction 切换器**；面包屑最前段加 Direction（带方向色点）。
- §4.1 文献库：增加 `directions` 过滤与「共用」徽章；筛选条加方向维度。
- §4.2 Idea 树：节点显示 `⎇ <branch>`；只渲染当前 Direction 的 Idea。
- §4.3 矩阵：标题加 Direction 名；行头 Idea 显示 branch。
- §4.4 实验详情：不变（仍 Version=commit）。
- §9 落地范围：**新增「表格视图 + 自定义列」为必做**；Direction 切换与过滤为必做。
- §10 自检新增：切换 Direction 后，文献/Idea/实验均只显示本方向内容；共用文献可见且标注。

### 11.6 移动端已砍（2026-08-31）
用户决策：**Idea Forge 是本地部署、数据全在本地磁盘，手机读不到本地数据，移动端没有意义。**
- **v0.1 不做任何移动端/响应式适配**；§6「移动端视图」整章作废。
- `data-density="comfortable"` 保留，仅作为桌面端的「舒适」显示模式，不再是移动端机制。
